# Диагностика vibe-mac

Начни с двух безопасных команд:

```bash
vibe-mac-verify
vibe-mac-doctor
```

Если versioned bundle ещё не установлен, запускай их из проверенного checkout:

```bash
/bin/bash ./verify.sh
/bin/bash ./doctor.sh
```

Обычный doctor ничего не меняет. Не используй `--repair`, пока не прочитал
показанный план.

## Mac не поддерживается

`vibe-mac` рассчитан на Apple Silicon и macOS 14+. Обнови macOS, затем
повтори запуск. Intel можно разрешить только как неподдерживаемый best-effort
режим:

```bash
ALLOW_UNSUPPORTED_INTEL=1 /bin/bash ./install.sh
```

Если preflight сообщает о нехватке места, освободи минимум 15 ГБ и запусти
установщик снова.

## Открылось окно Command Line Tools

Это ожидаемая ручная пауза. Нажми «Установить», дождись завершения системного
окна и вернись в Терминал. Затем повтори:

```bash
/bin/bash ./install.sh
```

Установщик заново проверит receipt и выбранный developer path.

## Homebrew просит подтверждение или пароль

Перед официальным установщиком `vibe-mac` показывает отдельную стоп-точку.
Вводи пароль только в видимом штатном Терминале; символы при вводе не
отображаются. Если ты не ожидал этот шаг, откажись и сначала выполни:

```bash
DRY_RUN=1 /bin/bash ./install.sh
```

`vibe-mac` не запускает upgrade, reinstall, cleanup или zap для уже
установленных прямых пакетов. Homebrew всё же может обновить нужную новому
пакету транзитивную зависимость; она будет отмечена в manifest.

## Установка остановилась

Сообщение содержит ID шага и путь к приватному логу:

```text
~/.vibe-mac/logs/install-<UTC-время>.log
```

Исправь указанную причину и снова запусти `/bin/bash ./install.sh`. Не удаляй
`progress.json`: выполненные шаги всё равно независимо перепроверяются, а
установка продолжается с первого незавершённого.

Не публикуй полный лог в чате или issue, пока не проверил его на личные данные.
Установщик маскирует известные чувствительные значения, но исходный вывод
сторонней команды может быть неожиданным.

## Сообщение о lock

Сначала запусти:

```bash
vibe-mac-doctor
```

Активный lock означает, что другая установка ещё работает. Не удаляй его
вручную. Если doctor доказал, что lock устарел, ограниченный ремонт доступен
так:

```bash
vibe-mac-doctor --repair
```

Команда покажет точную цель и спросит подтверждение. Повреждённый, сомнительный
или принадлежащий живому процессу lock автоматически не удаляется.

## Вход в аккаунт отложен или не завершён

Техническая установка может закончиться без входов. Повтори нужную официальную
команду в Терминале:

```bash
gh auth login --web --git-protocol https
claude auth login
codex login
cursor-agent login
open -a Cursor
```

Не вставляй API-ключи в установщик, конфиги, issue или сообщения. После входа
запусти `vibe-mac-verify`: статусы аккаунтов выводятся отдельно от 12
технических критериев.

## Не хочу менять Dock и Finder

Запускай установку с явным пропуском:

```bash
SKIP_DEFAULTS=1 /bin/bash ./install.sh
```

Без этого флага шаг показывает ровно две настройки и ждёт согласия: автоскрытие
Dock и показ расширений Finder.

## Каталог ~/dev/hello-vibe уже существует

Установщик намеренно останавливается и не меняет существующий каталог.
Проверь его содержимое и сам выбери новое имя или перенеси каталог. После этого
повтори установку. Автоматического удаления или объединения нет.

## verify показывает меньше 12 из 12

Каждая красная строка содержит одну точную команду восстановления. Выполняй
только подсказку этой строки, затем снова запускай:

```bash
vibe-mac-verify
```

Отложенный вход не уменьшает технический счётчик. Если вместо таблицы получен
integrity exit `2`, не подменяй файлы внутри release вручную.

## Bundle отсутствует или повреждён

До публичного релиза восстанови доверенный checkout из нужного commit и
запускай entrypoint из него. После выпуска релиза используй только immutable
versioned-команду из README с literal SHA-256 bootstrap.

Не скачивай случайный скрипт и не исполняй его через pipe. `bootstrap.sh` из
ветки разработки содержит placeholder и не является установочной командой.

## Безопасное удаление

Сначала посмотри план:

```bash
vibe-mac-uninstall
# или
/bin/bash ./uninstall.sh --dry-run
```

Применение требует `--apply` и точное слово `UNINSTALL`. Изменённые после
установки файлы и объекты без доказанного ownership сохраняются. Также всегда
сохраняются стартовый проект, аккаунты, credentials, Homebrew, Command Line
Tools, state, логи и резервные копии.

Если manifest отсутствует, повреждён или содержит небезопасный путь, удаление
останавливается без изменений. В таком случае ничего не удаляй рекурсивно:
сначала сохрани диагностику doctor и восстанови доверенный bundle.
